# PRD：字典编辑器与卡牌数据表交互统一

## 1. 概述

字典编辑器与卡牌数据表共享数据网格基础设施，但保留各自业务模型。字典继续使用现有 `.oclocale` 协议：记录为行，默认值与语言为列；语言单元格只存显式覆盖，未覆盖时继承默认值。

已确认的产品决策：

- 共享表格壳、列宽、单元格、选择、剪贴板和操作协议，不让字典直接依赖 `CardDataTable`。
- 保持“记录为行、语言为列”。
- 新增记录和语言入口移入表格。
- 第一阶段包含固定表头/首列、可调列宽、嵌入式字段、菜单、继承与重置、多选、复制粘贴和批量删除。

## 2. 目标

- 两个编辑器使用一致的表头、行高、单元格、滚动、列宽和操作反馈。
- 建立不包含卡牌或字典语义的共享数据网格模块。
- 支持连续区域、整行、整列选择以及 TSV 剪贴板交互。
- 支持批量删除记录/语言和批量清除值。
- 保持现有字典文件与运行时解析兼容。
- 所有视觉值来自 foundation token 或共享组件 contract。

## 3. 用户故事与验收条件

### US-001：共享数据网格基础设施

- [ ] 共享协议不含 card、instance、dictionary、language 等业务字段。
- [ ] 统一 scroll、colgroup、sticky 表头/首列、尾部操作列和列宽手柄。
- [ ] 列宽支持指针拖动及键盘方向键、Home、End。
- [ ] 表头、分组行、数据行和嵌入控件消费同一高度与 box-model contract。
- [ ] 新增视觉值先进入 foundation/theme。
- [ ] CardDataTable 迁移后原行为与测试不回退。
- [ ] 浏览器验证深浅主题与窄宽度布局。

### US-002：字典网格投影

- [ ] 第一列固定显示记录 key；第二列为默认值；后续列按语言插入顺序显示。
- [ ] 表头纵向滚动时固定。
- [ ] 默认值写回 `base[key]`。
- [ ] 语言格无覆盖时显示继承值与继承态，编辑时创建覆盖，重置时删除覆盖。
- [ ] 空字典仍显示可操作网格。
- [ ] `.oclocale` 序列化协议保持兼容。

### US-003：嵌入式单元格与操作轨

- [ ] 值单元格使用 `PropertyFieldRenderer` 的 embedded appearance。
- [ ] 嵌入控件不保留被单元格吸收的边框、padding、radius、背景或焦点几何。
- [ ] 重置覆盖使用 `PropertyFieldActionRail`。
- [ ] 只读、继承、覆盖、焦点状态与 CardDataTable 使用同一视觉契约。
- [ ] 操作轨出现或消失时不改变输入内容宽度。

### US-004：表格内新增

- [ ] 表头尾部提供添加语言入口。
- [ ] 表格底部提供添加记录入口。
- [ ] 输入在对应表头或首列原位出现。
- [ ] Enter 提交，Escape 取消；非法或重复 key 不可提交。
- [ ] 新记录产生空默认值，新语言产生空覆盖对象。
- [ ] 新入口完成后移除顶部旧新增表单。

### US-005：统一结构操作菜单

- [ ] 语言列使用 `OcActionButton` 提供重命名、删除、设为活动语言。
- [ ] 记录行使用 `OcActionButton` 提供重命名、删除。
- [ ] 相同命令可通过右键和键盘菜单触发，并进入同一 handler。
- [ ] 重命名原位完成，Enter/失焦提交，Escape 取消。
- [ ] 记录重命名迁移所有语言覆盖；删除记录清理所有覆盖。
- [ ] 删除活动语言时清除 `active`。
- [ ] 默认值列可设为活动来源，但不能重命名或删除。

### US-006：选择模型

- [ ] 单击值单元格建立焦点。
- [ ] Shift+单击或 Shift+方向键扩展连续矩形区域。
- [ ] 单击行头选择整行；Ctrl/Cmd+单击切换多个记录行。
- [ ] 单击列头选择整列；Ctrl/Cmd+单击切换多个语言列。
- [ ] 默认值列可选择和复制，但不可结构性删除。
- [ ] 选择态与活动语言态具有不同视觉语义。
- [ ] 选择只保存在编辑会话，不写入 `.oclocale`。
- [ ] 键盘焦点、ARIA 表格语义和 `aria-selected` 完整。

### US-007：TSV 复制粘贴

- [ ] Ctrl/Cmd+C 将连续值区域复制为 TSV。
- [ ] 继承格复制当前可见有效值。
- [ ] Ctrl/Cmd+V 从焦点格写入 TSV 矩阵。
- [ ] 粘贴默认值更新 base；粘贴语言格创建显式覆盖。
- [ ] 单值粘贴到多格选择时填充整个区域。
- [ ] 超出结构的内容不隐式创建行列，并给出反馈。
- [ ] key 列、表头和尾列不接受值粘贴。
- [ ] 一次粘贴只产生一次完整字典写回。
- [ ] 与至少一种电子表格软件互测 TSV。

### US-008：批量删除与清除

- [ ] 批量删除记录或语言前显示数量确认。
- [ ] 删除记录同步删除全部语言覆盖。
- [ ] 删除语言时必要地清除活动语言。
- [ ] Delete/Backspace 清除语言格时移除覆盖并恢复继承。
- [ ] 清除默认值时写入空字符串，不删除记录。
- [ ] 含糊的混合结构选择不执行破坏操作，并给出反馈。
- [ ] 批量操作只产生一次序列化写回。

### US-009：性能与稳定性

- [ ] 共享层支持可见区域按需挂载完整编辑器。
- [ ] 屏幕外格使用轻量预览，选择与剪贴板不依赖所有 DOM 同时存在。
- [ ] sticky、选择和按需挂载可同时工作。
- [ ] 数据变化后保持合理的焦点和滚动位置。
- [ ] 使用 1000 条记录 × 10 个语言列进行浏览器验证。
- [ ] TypeScript、UI lint、完整测试和生产构建通过。

## 4. 功能要求

- FR-1：共享网格只处理布局、导航、选择、列宽、剪贴板和 intent，不直接修改业务数据。
- FR-2：CardDataTable 与 DictionaryEditor 各自提供投影和 mutation handler。
- FR-3：记录和语言顺序沿用序列化对象插入顺序，稳定 key 不使用数组下标。
- FR-4：继承态由覆盖键是否存在决定，不通过字符串比较推断。
- FR-5：共享网格统一列宽、sticky 区域、行高和 box model。
- FR-6：剪贴板使用制表符分列、换行符分行，兼容 CRLF/LF。
- FR-7：粘贴不得隐式新增结构。
- FR-8：mutation 先构造完整 `ProjectDictionary`，再统一校验和序列化。
- FR-9：所有 destructive command 使用共享菜单/确认流程。
- FR-10：活动语言、选择、继承、焦点和无效输入必须有不同且可访问的表达。

## 5. 非目标

- 不修改 `.oclocale` 协议，不增加数据库式行 ID。
- 不把字典转换为卡牌实例或字段模型。
- 不让 DictionaryEditor 直接依赖 CardDataTable。
- 不加入机器翻译、翻译记忆、术语库或远程协作。
- 不支持粘贴时自动创建任意数量的记录或语言。
- 不改变运行时“默认值 + 活动语言覆盖”的解析行为。

## 6. 推荐技术边界

建立 `shared/ui/data-grid/`：

- `dataGrid.types.ts`：列、焦点、选择和 intent 协议。
- `useDataGridColumnSizing.ts`：指针/键盘列宽调整。
- `useDataGridSelection.ts`：焦点、矩形及行列选择。
- `useDataGridClipboard.ts`：TSV 编解码和剪贴板 intent。
- `OcDataGrid.vue`：仅在两处真实结构重复足够稳定时提取，不创建巨型万能 slot 组件。

字典侧增加纯投影/mutation 模块，集中实现新增、重命名、删除、覆盖、粘贴与批量操作。组件只渲染投影并上抛用户意图。

## 7. 实施顺序

1. 提取列宽、滚动/sticky 和共享几何，迁移 CardDataTable 且保持行为。
2. 建立字典纯投影与 mutation 测试。
3. 将字典迁移到共享网格并统一嵌入式字段。
4. 把新增、重命名、删除和活动语言操作迁入表格。
5. 加入焦点、矩形、整行和整列选择。
6. 加入 TSV 复制粘贴及批量删除。
7. 完成大数据量、键盘、深浅主题、全量测试和浏览器视觉验证。

每一步都必须保持可运行，不允许批量生成整套组件后一次性切换。

## 8. 成功标准

- 两个消费者不再各自维护列宽、选择或剪贴板实现。
- 两处表头、行、嵌入字段和列宽行为无明显偏差。
- 用户不离开表格即可维护记录和语言。
- 用户可在字典与电子表格之间往返复制翻译矩阵。
- 1000 × 10 数据量下常规滚动与编辑无明显长时间阻塞。
- 现有字典解析、序列化和运行时继承测试全部通过。

## 9. 实施中待定

- 列宽是仅会话保存，还是按字典文件路径写入软件级工作区缓存。
- 批量删除复用哪个标准确认对话框/服务。
- 整行复制是否包含记录 key，整列复制是否包含语言表头。
- 活动语言的快捷按钮是否保留，还是只进入列菜单。
