# `.opencard` 项目内核与项目字体系统升级

## 目标

将 OpenCard 管理的配置和项目级资源集中到项目根目录的 `.opencard` 文件夹，避免普通文件树暴露内部文件；随后重构项目字体系统，以“字体家族 + 字体组合”支持多字体面、字体集合和按字符范围回退，同时保持默认操作简单、高级能力可达。

本任务分成两个独立里程碑实施，直到完整测试与验收通过：

1. 项目内部结构重组。
2. 项目字体系统升级。

不增加旧格式迁移器、双格式读取或兼容分支；解析时只投影当前模型，缺失使用默认值，多余和未知内容忽略。现有卡牌中的 `font:<key>` 引用语法保持不变。

## 第一部分：项目内部结构

### 固定目录契约

```text
<project>/
├─ .opencard/
│  ├─ .ocproject
│  ├─ .ocblocks
│  ├─ .oclocale
│  ├─ .ocfonts
│  ├─ .ocicons
│  ├─ fonts/
│  ├─ icons/
│  └─ blocks/
└─ 用户文件...
```

- 建立统一的内部路径模块。项目配置、监听、保存、模板和导入逻辑只能通过该模块解析内部路径。
- 注册表中的资源路径相对 `.opencard`，分别形如 `fonts/name.ttf`、`icons/sheet.png`、`blocks/name.ocblock`。
- 新建或初始化项目时一次性创建全部五个内部文件和三个资源目录。
- 已有 `.opencard/.ocproject` 的项目若缺少其他内部项目项，安全补建缺失项；已有内容绝不覆盖。
- 任意普通目录都可直接作为工作区打开，不以 `.opencard` 是否存在判定或初始化项目。
- 根目录多出的旧版 `.oc*` 文件不参与项目判断，不读取、不移动，也不阻止初始化；当前 `.opencard` 结构缺项时静默补建默认内容。
- 初始化前预检目录、文件类型、符号链接和名称冲突，使用临时文件及重命名提交，失败时不留下半套结构。

### 文件树与项目管理树

- 普通文件树过滤整个 `.opencard` 子树，不显示、重排、拖放、重命名或删除任何内部文件。
- 侧栏新增独立“项目管理”树，固定包含：
  - 项目设置
  - 全局字典
  - 字体
  - 图标
  - 自定义块
- 节点是虚拟管理入口，点击后打开对应编辑器；不显示真实 `.oc*` 文件名，也不提供创建、删除、重命名和普通文件系统菜单。
- 五个入口在内部文件缺失时仍固定显示；首次点击任一入口时静默建立完整 `.opencard` 结构，再打开对应编辑器，不出现初始化提示。
- 字体、图标和自定义块入口分别把受管目录中的实际文件显示为子项；字体与图片使用对应预览器，`.ocblock` 使用自定义块包编辑器。
- 删除当前把 `.ocproject` 当父节点、其余四项挂载其下的特殊文件树投影，以及“新建 `.oc*` 文件”菜单。
- 内部文件不再作为可独立外部打开的资源；项目通过选择项目目录打开。

### 资源导入、设置与模板

- 删除应用设置中的默认字体导入目录和默认图标导入目录，包括类型、默认值、解析、写入、设置界面和全部语言文案。
- 字体、图标、自定义块固定导入各自的内部资源目录，不再允许用户配置目标目录。
- 仅当源文件已经位于对应 `.opencard` 资源目录时直接引用；项目其他位置和项目外文件均按外部资源处理并复制到内部目录。
- 导入前执行格式和安全验证。支持修复的字体只修改导入副本，不修改源文件。
- 内容相同的资源复用已有文件；同名但内容不同则自动生成不冲突名称并提示结果。
- 项目监听继续覆盖 `.opencard`，但普通文件索引和界面不暴露它。
- 项目模板必须完整包含 `.opencard`，且不可在模板导出选择器中排除。创建项目、模板校验、图标包和自定义块注册全部改用新路径。
- 该里程碑完成后更新用户向发布说明，描述根目录整理、资源自动管理和新的项目管理入口。

## 第二部分：字体系统

### 新 `.ocfonts` 模型

删除 `ProjectFont`、`ProjectFontSet`、递归字体集和旧解析兼容，替换为以下模型：

```ts
type ProjectFontFamily = {
  key: string
  name: string
  files: Partial<Record<'light' | 'normal' | 'bold', {
    upright?: string
    italic?: string
  }>>
}

type UnicodeRange = {
  start: number
  end: number
}

type ProjectFontCompositionMember = {
  fontKey: string
  ranges?: UnicodeRange[]
}

type ProjectFontComposition = {
  key: string
  name: string
  members: ProjectFontCompositionMember[]
}

type ProjectFontRegistryDocument = {
  families?: ProjectFontFamily[]
  compositions?: ProjectFontComposition[]
}
```

- 字体家族与字体组合的 Key 在同一命名空间内不区分大小写唯一。
- 字体组合只能引用字体家族，不允许嵌套组合。
- 六个字体槽位源路径必须安全、相对 `.opencard` 且位于 `fonts/`，并且至少填写一个槽位。
- 文档字重只保存 `light | normal | bold`，运行时固定映射为 `300 | 400 | 700`；字体元数据只用于导入时自动分槽，不进入注册表。
- Unicode 范围规范化为排序、去重、合并后的有效码点区间并排除代理项；空数组无效，省略 `ranges` 才表示不限范围。
- 解析器对缺失字段使用当前默认值，对未知或损坏条目给出诊断并忽略可恢复部分；不读取旧 `fonts/fontSets` 格式。

### 导入与管理体验

- 字体管理器只显示“项目字体”和“字体组合”，不显示独立字体文件记录。
- “导入字体”支持选择单个或多个 WOFF、WOFF2、TTF、OTF、TTC、OTC：
  - 单文件自动建立一个字体家族。
  - 多文件读取内部名称、字重和样式，并自动分配到三档字重的正体/斜体槽位。
  - 默认页面只展示第一个文件；“补充字重与斜体”入口展开完整六槽，空槽只显示自动回退提示。
- TTC/OTC 显示集合成员摘要并支持单选或多选；所选成员提取为独立 TTF/OTF 后写入 `fonts/`，不持久化集合索引。
- 外部或项目普通目录中的字体经过解析、字体引擎验证及可用时的安全修复，再复制到内部目录。
- 已位于 `.opencard/fonts` 的文件不复制、不改写，但仍须能解析后才能记录。
- 内容去重基于导入后实际字节；同名不同内容自动改名。
- 删除家族前检查组合引用并要求先移除或替换引用。
- 无引用字体文件在确认界面中默认勾选清理并通过回收站删除；仍被其他家族引用的文件绝不删除。

### 字体组合与运行时

- 组合成员严格自上而下匹配：第一个“范围匹配且所选字体面实际含有字形”的家族生效。
- 未指定范围的成员只接管前面成员未命中且自身字体面具有的字符；缺字继续向后回退，全部失败后使用系统后备字体。
- 范围编辑器提供常用文字系统预设、直接输入字符和高级 Unicode 区间三种入口，统一保存为 `UnicodeRange[]`。
- 为每个真实槽位按实际字形覆盖计算互不重叠的有效范围，并生成固定 `font-weight`、`font-style` 和 `unicode-range` 的 `@font-face`；空槽交给浏览器匹配或合成。
- `font:<key>` 可以引用字体家族或字体组合；所有编辑器、预览、卡牌渲染、导出和富文本共用同一解析与加载服务。
- 字体预览显示实际承载每段文字的项目字体和槽位，并诊断缺字、无效范围、被前项完全遮蔽的成员、缺失文件和加载失败。
- 自定义块打包同步升级为携带所需家族、组合及实际字体文件，确保项目预览、模板和导出结果一致。
- 该里程碑完成后更新用户向发布说明，描述多字体面家族、TTC/OTC、字符范围回退和简洁/高级双层操作体验。

## 已确定的默认决策

- `.opencard` 是由软件完全管理的内部目录，普通文件树整体隐藏。
- 新项目始终创建五个内部文件和三个资源目录。
- 任意普通目录直接打开；项目管理结构由相关能力按需建立，根目录多余 `.oc*` 文件忽略，不迁移也不阻止当前工作区打开。
- 使用独立项目管理树，不在普通文件树中重排虚拟项目项。
- 字体没有独立资产记录；家族字体面直接记录 `fonts/` 文件路径。
- 字体管理默认保持简洁，完整参数和字符规则通过高级入口展开。
- 字体组合只引用字体家族，不嵌套，采用严格列表顺序。
- TTC/OTC 导入后提取成员，不保存集合索引。
- 删除家族时确认清理孤立文件，仍被引用的文件始终保留。
