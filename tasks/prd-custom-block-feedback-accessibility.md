# PRD：Custom Block 操作反馈与无障碍语义

## 1. Introduction / Overview

OpenCard 已提供 Custom Block 导出、包注册和项目注册表管理能力，但这些流程中的部分动态反馈目前只通过颜色或孤立数字表达：导出失败和注册表导入失败不会被辅助技术主动播报；导出字段列表中的数字没有说明其代表引用次数。

本需求统一这些反馈的视觉与无障碍语义，使视觉用户、键盘用户和屏幕阅读器用户都能及时理解操作结果及字段引用信息。范围只覆盖 `v0.3.4..当前工作树` 新增的 Custom Block 界面，不包含既有卡片设计器样式债务或运行时架构调整。

## 2. Goals

- [x] 导出或导入失败后，错误信息立即成为可感知的动态反馈。
- [x] 错误反馈在导出对话框、注册表编辑器和同类 Custom Block 界面中采用一致语义。
- [x] 字段引用次数同时具备明确的视觉含义和可访问名称。
- [x] 复用现有 `OcDialog`、`OcTree`、`OcText` 和本地化体系，不创建功能重复的反馈组件。
- [x] 所有用户可见文案同步覆盖简体中文和英文。

## 3. User Stories

### US-001：播报 Custom Block 导出错误

**Description:** 作为使用屏幕阅读器导出 Custom Block 的用户，我希望导出失败时立即听到失败原因，以便修正内容后重试。

**Acceptance Criteria:**

- [x] `CustomBlockExportDialog` 的错误信息具备 `role="alert"` 或等价的 assertive live-region 语义。
- [x] 导出被绑定、包展开或接口冲突检查阻止时，屏幕阅读器可在错误文本出现后主动播报对应本地化消息。
- [x] 导出抛出异常时，同一错误区域播报通用失败消息，不暴露原始异常、内部路径或实现细节。
- [x] 新一次提交开始时清除旧错误；相同错误在后续独立提交中仍可再次播报。
- [x] 忙碌状态继续由现有 `aria-busy`、`inert` 和禁用控件表达，不新增第二套加载状态。
- [x] 组件测试断言错误区域的角色、显示条件及忙碌状态交互。
- [x] 类型检查、UI lint 和相关测试通过。
- [x] Verify in browser using browser control skill.

### US-002：播报注册表导入错误

**Description:** 作为使用屏幕阅读器管理项目 Custom Block 的用户，我希望文件选择或导入失败时听到错误信息，以便知道操作没有完成。

**Acceptance Criteria:**

- [x] `ProjectCustomBlockRegistryEditor` 的异步错误信息具备 `role="alert"` 或等价 live-region 语义。
- [x] 文件读取、包校验、复制或注册失败后，错误文本出现并被辅助技术主动播报。
- [x] 用户取消原生文件选择时不显示或播报错误。
- [x] 开始下一次导入前清除上一次错误；成功导入后不保留陈旧错误。
- [x] 错误反馈使用现有 `OcText` 危险语气及编辑器布局，不新建独立通知组件或自定义浮层。
- [x] 组件测试覆盖导入失败、取消选择和成功重试。
- [x] 类型检查、UI lint 和相关测试通过。
- [x] Verify in browser using browser control skill.

### US-003：明确字段引用次数

**Description:** 作为选择 Custom Block 公开字段的用户，我希望理解字段旁数字的含义，以便判断哪些字段应暴露给使用者。

**Acceptance Criteria:**

- [x] 每个字段的 `referenceCount` 不再以无说明的裸数字作为唯一表达。
- [x] 视觉界面明确表达数字代表引用次数，并保持字段名称为该行的主要信息。
- [x] 屏幕阅读器能读出字段名称和完整含义，例如“标题，引用 3 次”，而不是仅朗读“标题，3”。
- [x] `0` 次引用仍显示或提供等价可访问信息，不能因假值判断而消失。
- [x] 单数、复数或中文量词通过本地化文案处理，不在组件中拼接固定语言文本。
- [x] 中英文语言文件使用同一个翻译键并表达相同语义。
- [x] `OcTree` 的通用 `tail` 契约不被改造成 Custom Block 专用 API；如需新增可访问标签，应设计为可复用的树项能力。
- [x] 组件测试覆盖 `0`、`1` 和多个引用的渲染与可访问名称。
- [x] 类型检查、UI lint 和相关测试通过。
- [x] Verify in browser using browser control skill.

### US-004：统一验证操作反馈

**Description:** 作为维护 Custom Block 界面的开发者，我希望相关反馈遵循同一组件和测试契约，以便后续功能不会重新引入只靠颜色表达的状态。

**Acceptance Criteria:**

- [x] 导出对话框与注册表编辑器使用相同的错误语义规则：危险色负责视觉提示，live region 负责动态播报。
- [x] 错误信息不能只依赖颜色、图标或焦点移动传达。
- [x] 不修改 `OcDialog` 的模态职责，不在功能组件内实现自定义焦点陷阱、遮罩或通知层。
- [x] 不为三处局部文案新增重复的 feature-local 样式或魔法视觉值。
- [x] 浏览器验证覆盖键盘操作、可见错误状态、长中英文文案和窄视口布局。
- [x] 项目支持的全部语言同步更新，不存在单语言新增或修改翻译键。
- [x] 用户可见改进在 `opencard-app/RELEASE_NOTES.md` 中以用户语言记录。
- [x] Verify in browser using browser control skill.

## 4. Functional Requirements

- [x] **FR-1:** Custom Block 导出失败消息必须位于可被辅助技术主动播报的错误区域中。
- [x] **FR-2:** Custom Block 注册表导入失败消息必须使用与导出错误一致的动态错误语义。
- [x] **FR-3:** 错误区域只在存在错误文本时渲染，不能在正常状态产生空播报。
- [x] **FR-4:** 每次新操作开始前必须清除该流程的旧错误，成功完成后不得残留失败状态。
- [x] **FR-5:** 用户取消文件选择不属于错误，不得显示失败消息或触发错误播报。
- [x] **FR-6:** 用户界面只能显示本地化、面向用户的错误文案，不得直接显示堆栈、内部文件路径或原始异常对象。
- [x] **FR-7:** 导出字段列表必须说明 `referenceCount` 的含义，并为每个字段提供完整的可访问描述。
- [x] **FR-8:** 引用次数文案必须支持 `0`、`1` 和多个引用，不得依赖英文专用的字符串拼接规则。
- [x] **FR-9:** 新增或修改的翻译键必须同时更新 `zh-CN` 和 `en-US`。
- [x] **FR-10:** 实现必须优先复用现有基础与标准组件；任何共享树项能力扩展必须保持领域无关。
- [x] **FR-11:** 新增样式必须使用现有语义 token；本需求不得引入颜色、间距、尺寸、半径、动画或断点的字面视觉值。
- [x] **FR-12:** 所有修改必须通过类型检查、UI lint、相关单元测试和浏览器交互验证。
- [x] **FR-13:** 实现该用户可见改进时必须同步更新 `opencard-app/RELEASE_NOTES.md`。

## 5. Non-Goals / Out of Scope

- 不治理 `CardDesignEditor.vue` 中早于本次基线存在的布局尺寸、断点或动画字面值。
- 不重构 Custom Block 导出、打包、资源加载、注册表持久化或渲染管线。
- 不新增全局通知中心、Toast 系统或错误日志界面。
- 不改变 `.ocblock` 文件格式、接口哈希、注册表格式或导入冲突策略。
- 不修改 `OcDialog` 的焦点管理、Tab containment、关闭来源或表面几何契约。
- 不重新设计字段公开/私有分组、拖放流程或字段分析算法。
- 不在本需求中处理尚未由审查证明的删除并发问题。

## 6. Design Considerations

### 错误反馈

- 错误文本保留在触发操作的局部上下文内，避免用户在对话框或编辑器之外寻找结果。
- 使用现有危险语气文本样式，同时补齐动态播报语义；颜色不能成为唯一信息载体。
- 不通过强制移动焦点播报普通可恢复错误，以免打断键盘用户当前操作。
- 忙碌期间继续禁止重复提交；错误出现后恢复原有可操作控件，允许用户修正并重试。

### 引用次数

- 字段名称保持树行主要标签；引用次数作为次要信息呈现。
- 可见文案应短而明确，例如“3 次引用”或“3 references”。
- 若紧凑布局只适合显示数字，可见区域可以保持紧凑，但必须通过共享树项的可访问标签提供完整含义，并保证含义可被视觉用户发现，例如通过列表标题或列语义说明。
- 不使用仅悬停可见的 Tooltip 作为唯一解释，因为触屏和键盘用户不能稳定依赖悬停。

## 7. Technical Considerations

- `CustomBlockExportDialog.vue` 已使用 `OcDialog` 的 `aria-busy` 与 `inert`；实现应在此基础上补充错误 live region，不应重复管理模态状态。
- `ProjectCustomBlockRegistryEditor.vue` 已通过 `error` 状态承载导入异常；实现应复用该状态并补齐语义及测试。
- `CustomBlockExportDialog.vue` 当前通过 `OcTreeItem.tail` 输出 `referenceCount`。优先考虑传入完整的本地化尾部文案；若需要区分可见尾部和可访问名称，应为共享 `OcTreeItem` 增加通用字段，并同步补充 `OcTree` 测试。
- 所有新增测试应以用户可观察行为为断言重点，包括角色、文本、禁用状态和可访问名称，避免只断言内部 ref。
- 浏览器验证应至少覆盖中文、英文和窄视口；确认错误文本不溢出，不遮挡 footer，也不会造成对话框布局跳出视口。
