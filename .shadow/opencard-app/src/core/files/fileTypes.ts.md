`fileTypes.ts` 是文件语义的唯一入口，不要再把“扩展名 -> 编辑器 / language / 图标 / 颜色 / 预览能力”重新拆回 view、store 或 editor registry。

这里的核心承诺是：新增一种文件类型时，优先只在这里声明它的语义；只有当该类型需要全新编辑器实现时，才去补一个新的 editor component 并在编辑器注册中心挂上 `editorId`。

未来如果出现特殊文件名优先级、文件模板、创建向导、只读/二进制限制，也应该继续附着在这层语义定义上，而不是让调用方自己 `if ext === ...`。

图标颜色同样如此。页面层不应该知道 “TS 是蓝色、Vue 是绿色”；这些属于文件类型语义，应继续由这里统一产出。
