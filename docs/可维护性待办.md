# OpenCard 可维护性待办

本文件是当前专项会话的持久化工作清单，用于渐进处理 OpenCard 的可维护性、代码统一度和轻量开发规范。

## 维护者改动偏好

- 渐进推进，每轮只处理一个明确问题。
- 每轮先陈述问题和重要性；只有在维护者跟进或要求后，才继续分析、规划或实现。
- 维护者保留范围和方向的决定权，不擅自扩大任务或顺带重构。
- 优先采用最小但充分可靠的改动，尽量复用现有能力。
- 代码应按天然职责落位；既避免逻辑东拼西凑，也避免把不同用例塞入一个巨型模块。
- 不按行数机械拆文件。只有职责混杂、修改半径过大或无法独立测试时，才按完整用例抽离。
- 不为理论纯粹引入不必要的新层级、接口、Store、事件总线或复杂状态机。
- 规则应少而关键：数据安全、状态真相、持久化格式和跨模块协议是硬约束，其余允许有理由的例外。
- 测试优先覆盖真实风险和关键契约，不追求形式化覆盖率数字。
- 方案应方便开源贡献者理解和扩展，但不能因流程过严限制项目发展。
- 当前阶段优先选择简单方案；只有真实需求或测量证据出现后，才升级为更复杂的设计。
- 任何实现建议都要同时说明维护成本和复杂度代价，不能只追求架构上的理论最佳。
- 每项任务完成后，固定总结具体做了什么、每件事意味着什么，以及待办表中的下一项。

概括：用最少但足够可靠的改动解决真实问题，使代码边界清楚、容易理解和测试，同时不给未来发展增加不必要的框架与规则。

## 当前问题

### M-001：编辑器卸载可能丢失最后一次输入

**问题**

Card Designer 将 typing 变更延迟约 300ms 后序列化并同步到 session draft。切换编辑器会卸载当前 Designer，而卸载流程会取消尚未执行的 timer，不会先提交 pending change。因此，用户输入后立即切换 tab 时，界面虽然已经显示为 modified，最后一次文档状态却可能尚未写入 session draft。

**重要性**

这是最高优先级问题，因为它可能直接造成用户内容丢失，并且暴露了编辑器内部状态与 session 真相边界之间缺少可靠的交接协议。若这个基础契约未解决，后续项目切换、关闭确认、自动保存和多编辑器扩展都会建立在不稳定的生命周期之上。

**已确认设计**

采用符合当前体量的最小生命周期修复：

- 保留现有 300ms typing debounce 和 undo 合并方式，不引入第二套 draft/history 同步流程。
- `dispose()` 在释放 timer 前同步提交 pending typing，复用已有 `flushPendingChangesSync()`。
- Shell 传给编辑器的更新回调必须绑定创建 props 时的稳定 `session.id`，不得在回调执行时重新读取可能已切换的 `activeSession`。
- 修复只落在文档状态生命周期与 Shell session 路由两个天然职责点，不增加新模块、Store 或事件协议。

**验收条件**

- typing 后立即切换或卸载编辑器，重新打开原 session 时内容完整。
- session A 卸载期间产生的最终回调不会写入 session B。
- 连续 typing 仍合并为一条 undo 记录；action change 仍立即形成独立记录。
- 卸载后没有残留 timer 或延迟回调。

**完成记录（2026-07-27）**

- `useCdeDocumentState.dispose()` 改为复用 `flushPendingChangesSync()`，销毁时不再丢弃 pending typing。
- Shell 的两类编辑器 draft 更新回调均闭包绑定生成 props 时的稳定 session id。
- 新增生命周期回归测试，验证 dispose 会提交最新文档并清除 timer。
- 定向测试：3 个测试文件、11 个测试通过。
- 全量测试：83 个测试文件、378 个测试通过。
- `npm run build` 与 `npm run lint:ui` 通过。

### M-002：项目切换会删除旧 workspace sessions

**问题**

当前三个项目切换入口都会调用 `closeWorkspaceSessions()`，直接删除旧项目的 workspace sessions；但 session 设计要求路径可以改变而身份、draft、dirty 和 UI state 不应丢失。现有 project-switch 测试还把删除旧 session 固定为正确行为。

**重要性**

这是极高优先级问题，因为切换项目可能直接丢失未保存内容，并且代码、测试和设计记录对正确行为没有统一答案。

**修复方案**

- 在 `editorSessionStore` 增加 `detachWorkspaceSessions(oldRoot)`，不新增模块或状态类型。
- 对每个 workspace session：相对路径拼接到 `oldRoot` 并规范化为绝对路径，已有绝对路径保持不变，然后将 `resourceKind` 改为 `external`。
- session id、name、file type、editor id、saved/draft content、dirty、preview、active 状态和 UI state 全部原样保留。
- 仅在“旧项目切换到另一个项目”的三个入口使用 detach：目录选择打开、最近项目打开、新项目创建后激活。
- 显式“关闭项目”继续使用现有 close 行为，留给 M-003 的统一未保存会话关闭事务处理。
- 保留 `closeWorkspaceSessions()`，不进行无关重命名或抽象。

**验收条件**

- 切换项目后，旧 workspace session 保持同一个 id，并成为指向旧项目绝对路径的 external session。
- dirty draft、saved content、preview 状态和 Card Designer UI state 均不变化。
- 当前活动 session 若来自旧项目，切换后仍保持活动，不被静默替换。
- 新项目可以打开相同的相对路径，并创建独立的 workspace session，不与旧 external session 冲突。
- 原本已经是 external 或 draft 的 sessions 不发生变化。

**完成记录（2026-07-28）**

- `editorSessionStore` 新增 `detachWorkspaceSessions(oldRoot)`；切换项目时将旧 workspace 相对路径固化为旧项目下的绝对路径，并转为 external。
- 会话 id、draft/dirty、preview、活动态与编辑器 UI state 全部保留；external 和 draft 不受影响。
- 目录选择、最近项目和创建项目三个切换入口改用 detach；显式关闭项目仍使用 `closeWorkspaceSessions()`。
- 新项目可以独立打开同名相对路径，不与旧项目的 external session 冲突。
- 关闭项目和删除目录的现有行为不在本任务中改变。

### M-003：关闭动作缺少统一的未保存编辑器拦截

**问题**

关闭项目、关闭软件、关闭 tab 或删除目录时，当前实现可以直接删除受影响的 sessions，没有统一检查 dirty editors 与尚未落盘的 draft，也没有给用户保存、放弃或取消的机会。窗口标题栏关闭和系统窗口关闭同样需要进入这条保护链路。

**重要性**

这是极高优先级问题，因为这些动作会真正结束 session 生命周期；如果缺少统一拦截，任何一个入口都可能绕过保存并造成数据丢失。

**建议交互**

- “需要关闭保护”的统一条件是 `session.resourceKind === 'draft' || session.isDirty`；draft 即使尚未被编辑、`isDirty === false`，也没有磁盘副本，不能静默丢弃。
- 仅当本次关闭动作实际影响的 sessions 中存在需要关闭保护的 editor 时弹窗；否则直接继续。
- 关闭项目只检查将被关闭的 workspace sessions；external 与 draft 会继续存在，不参与该弹窗。
- 关闭软件检查全部 dirty sessions 和全部 draft sessions；关闭 tab 检查该 session；删除目录检查目录内将被关闭的 sessions。
- 弹窗顶部提供“全选未决定项”；它只选择仍未决定去留的行。
- 每行提供文件图标、名称和可区分同名文件的路径，并具有独立决定状态：`未决定去留`（warning）、`将存储到 …`（success）、`将放弃保存`（danger）。状态必须同时使用图标和文字，不能只依赖颜色。
- 只有 `未决定去留` 的行显示 checkbox。批量设置完成后，该行取消选择并隐藏 checkbox，但继续留在原位置供用户核对，避免选择态与决定态混淆。
- 已决定行提供轻量的 `更改` 操作；点击后恢复为 `未决定去留` 并重新显示 checkbox，不需要额外的批量撤销协议。
- 批量操作区提供 `设为放弃（x 个选中）` 与 `保存（x 个选中）到…`，未选择行时均禁用。
- 底部提供 `取消` 与主操作 `确认去留`；只要存在 `未决定去留` 的行，`确认去留` 就保持禁用。
- `取消`恢复到拦截前状态，不关闭 session、不切换页面、不退出软件。

**批量保存决定**

- `保存（x 个选中）到…` 对已有磁盘路径的 dirty sessions 直接记录为原位保存，不弹文件选择器。
- 若选中项包含 drafts，只通过系统目录选择器选择一次目标文件夹；这些 drafts 默认使用当前名称与扩展名，并记录为 `将存储到 <目标路径>`。
- OpenCard draft 默认使用最新文档 `name` 与 `.opencard` 扩展名，其他 draft 复用当前名称与文件类型扩展名；与目标目录现有文件或同批草稿重名时自动追加递增后缀，并在 `将存储到` 路径中明确展示，不静默覆盖。
- 首版同一次批量操作中的 drafts 使用同一目录；需要不同目录时，可分批选择并分别执行 `保存到…`，不增加逐行目录配置。
- `将存储到` 表示已经决定目标、尚未实际写盘；真正保存只在点击 `确认去留` 后开始，执行中再显示 `保存中`，成功后显示 `已保存`。

**安全语义**

- 点击 `确认去留` 后先执行所有 `将存储到` 项；只有它们全部保存成功，才处理 `将放弃保存` 项并继续原关闭动作。
- 任一实际保存失败时中止关闭；已经保存成功的项目保持 clean，失败项目保留 dirty，并在弹窗中显示错误。
- 保存 draft 成功后按实际路径转为 workspace 或 external session；目录选择取消只取消本次批量决定，不关闭软件，也不改变这些行原有决定。
- `全部放弃`会永久丢失 draft 的内存内容，必须使用危险操作样式和明确文案。
- 用户作出决定之前，不提前删除 session、清空项目状态或关闭窗口。
- 系统窗口关闭事件必须先同步 `preventDefault()`；确认完成后使用 Tauri `Window.destroy()` 强制销毁窗口，不得重新发起窗口关闭并再次进入拦截链。
- 项目切换在 M-002 完成后只 detach sessions、不结束其生命周期，因此不触发该弹窗。

**最小实现边界**

- 新增一个专用 `UnsavedEditorsDialog` 展示列表和按钮，不把弹窗模板继续塞入 `OpenCardShell.vue`。
- Shell 只维护一个带类型的 pending close intent，并统一执行检查、等待用户决定和继续原动作。
- `editorSessionStore` 继续拥有 dirty、save 和 close 真相；不把弹窗状态或用户选择写入 store。
- 不引入全局事件总线、第二个 session store 或通用工作流框架。
- 先覆盖关闭项目和关闭软件；单 tab 与删除目录复用同一入口，不各写一套弹窗逻辑。

**完成记录（2026-07-28）**

- 新增单一 `useUnsavedSessionGuard`，统一保护关闭项目、关闭应用、关闭 tab 和删除路径四类 session 结束动作。
- 保护条件统一为 `resourceKind === 'draft' || isDirty`，未修改但未落盘的 draft 不再被静默丢弃。
- 新增三态 `UnsavedEditorsDialog`：pending 行显示 checkbox，save/discard 行隐藏 checkbox 并保留“更改”，存在 pending 时确认禁用。
- 多 draft 只选择一次目录，自动为同批或磁盘重名目标追加递增后缀；已有路径的 dirty session 原位保存。
- 真正执行时先保存全部 save 决定，任一失败即阻断关闭；保存全部成功后才执行 discard 与原关闭 intent。
- Card Designer 向 Shell 暴露同步 `flush()`，关闭检查前确保 pending typing 已写回 session draft。
- 自绘窗口关闭与 Tauri `onCloseRequested` 进入同一 guard；最终退出由官方 `Window.destroy()` 完成。
- 新增 3 个测试文件；全量验证为 86 个测试文件、387 个测试通过，`npm run build` 与 `npm run lint:ui` 通过。
- 使用本地浏览器验证 2 个 draft 的初始、全部放弃、更改决定和 600px 窄窗口状态；视觉证据保存在被忽略的 `output/playwright/`。

**退出续执行修复（2026-07-28）**

- 修复确认去留后重新调用 `window.close()`、再次进入 Tauri 关闭请求链而未可靠退出的问题。
- 最终退出改为在保存/放弃全部完成后调用官方 `Window.destroy()`；它不会重入 `closeRequested`，也会避免立即结束进程造成的 WebView 清理错误。

- 关闭只影响一个未保存编辑器时使用紧凑确认框：文件名放入标题，只保留一句风险说明与“取消 / 丢弃 / 保存”，不显示多项文件卡片和状态信息；保存或丢弃后立即续执行原关闭动作。多项时保留完整批量决定界面。

### M-003A：关闭项目并返回欢迎页

**问题**

现有“关闭项目文件夹”会安全结束项目上下文，但按设计保留当前 Shell 页面。用户缺少一个明确命令，在关闭项目后直接结束当前工作上下文并返回欢迎页。

**重要性**

### M-014：大型项目下 Viewport 动画卡顿

**问题**

Card Viewport 的平滑缩放逐帧上抛 transform，Shell 又逐帧调用 `updateSessionUiState()` 替换 sessions 数组。大型项目下，这会让活动会话、打开编辑器和 Sidebar 文件树在动画期间持续参与响应式更新。

**重要性**

高。它让项目规模直接污染编辑器局部动画性能；用户打开下载目录等大型文件夹时，其它离散操作尚可，但最常用的缩放反馈明显掉帧。

**完成记录（2026-07-28）**

- Viewport 与 Card Designer 继续在本地逐帧更新，保持缩放栏、Navigator 与画布同步。
- Shell 将 transform 的 session UI state 持久化改为 200ms 尾随提交，动画期间不再逐帧替换 sessions 数组。
- pending transform 携带稳定 session id；切换 session 或 Shell 卸载时先提交，避免写入后来激活的编辑器。

### M-015：Session 更新放大到 Sidebar/Tree

**问题**

`updateDraftContent()` 等会话更新会替换整个 sessions 数组，继而重算 `activeSession` 与 `openedEditorItems`。`useShellFileTree` 又监听完整 active session 对象，并在每次变化时无条件创建新的 selected key 数组，即使 session id/path 根本没变。

**重要性**

中高。这是 M-014 的剩余放大器；虽然输入频率低于动画帧，但 Monaco 持续输入、dirty/UI state 更新仍可能让大型文件树执行无意义 patch。

**解决**

- `openedEditorItems` 按实际展示字段复用 item 与数组引用；仅 UI state、已 dirty 内容等无关变化不再重建 Tree 输入。
- 文件树只监听 active session 的 id/resourceKind/path，并在 key 未变化时保留 selected key 数组引用。
- 契约测试覆盖无关 UI/内容变化下的派生引用稳定性。

### M-016：设置 Slider preview 直接持久化

**问题**

设置页把 `OcSlider.preview` 的每次 pointermove 直接发送到全局 settings store；store 每次替换完整 settings 对象，并把一个新的持久化快照加入串行写队列。

**重要性**

中。实时主题预览需要局部连续更新，但不应把每个中间值都当成需要持久化的最终设置，否则快速拖动会产生响应式扩散和多余写盘。

**解决**

- 设置意图区分 `setting.preview` 与 `setting.change`：拖动保留全局实时外观反馈，只有 commit 进入持久化队列。
- 测试固定连续 20 次 preview 不保存、commit 只保存一次。
- `lint:controls` 禁止基础/标准控件直接依赖业务 store 或 persistence，约束高频交互先通过语义事件交给上层。

### M-017：大型项目打开被全量目录扫描阻塞

**问题**

项目激活和 Shell 挂载都会触发无限深度目录扫描。文件数量很大时，进入工作台必须等待整个目录树串行读取完成，看起来就像项目无法打开；这也绕过了文件树和路径补全已经具备的按目录加载能力。

**重要性**

高。项目规模直接阻塞应用主入口，而且扫描成本取决于用户选择的任意文件夹，无法给出稳定的打开时延。

**解决**

- 项目激活只设置项目路径、加载根目录和恢复过的展开目录，不再等待无限深度扫描；Shell 启动也不再主动预热完整项目树。
- 文件树展开继续按一层读取；文件路径自动补全在输入进入某个目录时只读取该目录，因此无需完整项目索引也能继续补全。
- 无限深度扫描保留为模板导出前的显式准备步骤，不再进入普通项目打开链路。
- 契约测试固定项目激活零全量扫描、根目录读取深度有限、补全只读取当前目录，以及显式完整加载仍可用于确有需要的操作。

### M-018：更新说明存在多份发布真相

**问题**

GitHub Action 将 Release Body 写死为占位文本，而应用只消费 updater 版本号。Release 页面后续人工修改不会回写 `latest.json`，安装重启后 updater 又不再返回当前版本，导致可用版本与当前版本的说明都无法可靠展示。

**重要性**

中高。发布说明属于用户判断是否升级以及理解版本变化的核心信息；多份来源会让应用展示过期内容，也让发版操作依赖容易遗漏的人工补救。

**解决**

- `release.ps1` 保持唯一发版入口，校验并纳入 `RELEASE_NOTES.md`，同时继续完成版本、检查、提交、标签、推送和 workflow 等待。
- GitHub Action 从 tag 对应提交读取同一份 Markdown，同时生成 Release Body 与 updater `notes`；安装包也内置该文件作为新安装时的回退来源。
- updater 用独立 `update-state.json` 保存当前版本说明、`seenAt` 和待安装版本说明；安装重启后按版本晋升，不污染用户设置。
- 首次进入新版本默认自动展示，关闭后才标记已读；用户可在设置中关闭自动展示，关于页仍显示缓存说明，并在有新版本时从版本号旁进入下载说明。

### M-006：按完整用例收敛 CardDesignEditor

**目标边界**

`CardDesignEditor.vue` 最终只保留模板组合、当前模式/Face/稳定 selection key，以及 `save/flush/undo/redo/navigate` 对外协议。跨结构树、属性面板和数据表的 Issue 导航仍由它协调；文档写回规则、DOM 生命周期、Render Pipeline、字段补全和 Viewport 几何不得继续直接实现于组件中。

**分阶段计划**

1. `M-006A useCdeOverlayLayout`：四面板展开、尺寸、拖拽、吸附、body cursor 与 DOM listener 清理；不得吸收 active Face、clip 或 view state。
2. `M-006B1 useCdePropertyEditorProjection`：只负责当前 PropertyEditor 的 reference scope、Binding/字体补全和字段 enrichment；文件 IO 只通过注入 provider 使用。
3. `M-006B2 useCdeDataTableCellProjection`：单独负责逐 Cell context、按需 definition 和缓存失效，不读取当前 PropertyEditor selection。
4. `M-006C useCdeDataTableCommands`：只负责数据表字段配置和 Cell 文档写回；保留 `useCdeDataTableModel` 的纯投影职责。
5. `M-006D useCdeRenderProjection`：只负责 `runRenderPipeline -> viewDoc -> viewFace`；Issue 继续复用纯函数，信息高亮不进入该模块。
6. `M-006E useCdeViewportController`：viewport transform、Navigator、ResizeObserver、缩放与 fit；文件加载完成后由编排层显式调用，不自行监听并竞争文档加载。
7. `M-006F useCdeSelectionCommands`：只负责 move、resize、快捷布局和 Face 尺寸的文档修改，不注册 DOM 事件。
8. `M-006G useCdeLayerViewInteraction`：只负责 Tab/Space/方向键状态和路由，通过注入命令调整层级，不直接拥有文档真相。

每阶段单独审批、实施和验证；不得为了减少往返一次创建全部模块。

**防止再次形成大杂烩的硬规则**

- 按完整用例划分，不按行数划分。新模块必须能用一句“负责什么、不负责什么”描述；“工具集”“上下文”“控制器”不能成为吸收无关逻辑的理由。
- 每个模块只能拥有一个状态真相。投影模块不得修改文档；命令模块不得维护第二份文档、selection 或 viewport；交互模块只能保存完成交互所需的瞬时状态。
- 每个模块只允许一类主要副作用：文档写回、DOM 生命周期、文件 IO 或上抛事件四者不能在同一模块混合。唯一例外是完整交互事务内部的 DOM listener 注册与对应清理，二者必须成对并由同一模块负责。
- 新模块禁止导入 `EditorProps`、`EditorEmits`、editor registry、`CardDesignEditor.vue` 或其他 controller。它只能消费精确的 readonly ref、稳定 id 和语义命令；controller 间协作由 `CardDesignEditor` 显式注入，不允许相互引用形成新网络。
- 禁止把整个 `props`、整个 store 或可变领域对象当作便利参数传入。需要项目上下文时传 readonly 投影；需要 IO 时传窄 provider；需要修改时传明确命令。
- 公共 payload 必须命名并固定字段，事件语义与状态语义一一对应。不得使用 `unknown`、无含义对象或同时支持新旧字段的兼容协议绕开边界。
- 如果一个新模块必须挂载完整 `CardDesignEditor` 才能测试，或一个需求修改需要同时打开三个新模块，视为边界失败，必须暂停并重新审查，而不是继续向模块追加参数。
- `CardDesignEditor` 仍可保留真正的跨用例协调，但不得把已迁移实现以 wrapper、别名或 fallback 形式留在原组件。每阶段结束必须检索旧函数名与旧 listener，残留为零。
- 不以文件行数作为完成标准。完成标准是状态真相唯一、依赖方向单向、每个模块可独立测试，并且外部编辑器协议与用户行为不变。

**阶段验收闸门**

- 实施前列出精确输入、输出、payload 字段、唯一调用方和旧符号清理表达式。
- 先添加当前高风险行为的 characterization test，再迁移实现；原有 `CardDesignEditor.navigation.spec.ts` 作为集成回归保留。
- 每阶段必须通过定向测试、完整测试、类型检查、`lint:ui` 与 `git diff --check`；涉及构建边界时再运行生产构建。
- 每个新增重要模块建立对应 `.shadow`，记录状态真相、允许副作用和禁止依赖。
- M-006 属于内部职责重构；没有用户可见变化时不写发布说明。

**实施前置条件**

当前主题系统和 `CardDesignEditor.vue` 的功能改动已先形成独立检查点，后续阶段继续根据上一阶段结果逐个审批，不与新的用户功能混入同一 diff。
